## 🌅 What it is

**Bom Dia, Claude** is Odyssey's daily morning ritual: a single visual briefing designed to open the day with the information Odara needs, while preserving surprise, playfulness and a small amount of chaos.

The current Scheduled Task is technically named **Card Pull of the Day**, but the card is not the task's functional purpose. The tarot-style card is the ritual's visual/narrative opening device. The actual workflow is a broader daily briefing.

> **Core idea:** one morning ritual, many useful signals, presented as an experience rather than a dry information dump.
>

## 🃏 The role of the Card Pull

The daily card is the centerpiece of the experience, not the definition of the Skill.

It uses an Odyssey-authored tarot-like deck and a flip interaction. The revealed phrase is not a canonical tarot interpretation; it is a daily narrative prompt generated in context.

The card can therefore be understood as the **ritual / experience layer** of the morning briefing.

It should not be extracted into a separate Persona merely because the ritual uses tarot language.

## 🧭 Purpose

The intended experience is:

1. Open one morning ritual.
2. Quickly understand what matters today.
3. See relevant personal context, obligations and external signals.
4. Receive a small element of surprise or play.
5. Have useful actions available without turning the ritual into another task-management system.

The original design principle was a light daily touch with low cognitive load. The current ritual has grown richer, but that principle remains relevant.

## 🗺️ Current page structure

The current documented order is:

1. **Greeting** — “Bom dia, Odara”, compass/seal and fixed tagline.
2. **Weather + date**
3. **A Carta do Dia** — visual/narrative centerpiece.
4. **Flo + Hoje** — cycle context and a short day-context line.
5. **Word of the Day + Soundtrack** — colloquial Spanish/Catalan plus music selected from the entertainment/music profile.
6. **Mini Side Quest** — a small daily challenge that does not become an Obligation.
7. **Tasks & Obligations** — Today / Week / Month, with rigid items prioritized.
8. **Calendar Check** — Google Calendar, with Fortis Early Meeting first when applicable.
9. **Odyssey Gazette** — News, Events and Correspondence.
10. **Feedback Accumulated** — lightweight feedback capture and handoff to Claude.
11. **Poções / Quick Actions** — action buttons read from the Quick Actions registry.

The visual layer is mobile-first and uses the approved tarot-table aesthetic. The current production artifact is the living technical reference for the visual implementation.

## 🧪 Reusable Skills / Poções extracted from the ritual

The morning ritual should **compose** reusable capabilities rather than own every capability exclusively.

The following are examples of capabilities that belong as independent Skills / Poções and may also be invoked by the morning ritual:

- 🧭 **Side Quest Generation** — generate a small, context-aware optional challenge.
- 📧 **Personal Gmail Quick Sweep** — rapidly surface relevant inbox items that deserve attention.
- 📰 **Daily News Briefing** — curate relevant news rather than dumping headlines.
- 📅 **Calendar Check** — surface relevant events and important scheduling context.
- 🎵 **Soundtrack Selection** — choose a song from the established music profile for the day's energy.
- 🗣️ **Word of the Day** — provide a useful colloquial Spanish/Catalan expression.
- 🧹 **Task / Backlog Check** — surface today's relevant obligations without replacing the task system.
- 🌆 **Local Events / Discovery** — surface relevant Barcelona/European events when appropriate.
- 🧪 **Quick Actions** — expose active reusable actions from the Quick Actions registry.

These are **capabilities**, not additional Personas.

The ritual can orchestrate them; they should remain independently useful when invoked outside the ritual.

## ▶️ Manual / on-demand execution

The desired architecture is:

**Scheduled Task** → automatically runs at the configured time

**Same Scheduled Task** → can also be manually triggered on demand

The manual trigger should execute the same core workflow rather than create a second implementation.

This prevents divergence between “morning run” and “run it now”.

## 🧱 Production / experiment discipline

This task is production-critical enough that changes should follow the Odyssey rule:

> **Experiment freely. Protect what works. Promote only after it has been validated.**
> 

For this workflow:

1. Visual or structural changes are developed separately from the production version.
2. Functional changes are tested end-to-end before becoming the source for future scheduled runs.
3. The living reference artifact is the current technical implementation reference.
4. Notion documents intent, behavior, history and architecture; it should not silently claim that a database-driven feature is live when the production artifact still hardcodes it.
5. The functional core should remain usable even if progressive enhancements fail.

## ⚠️ Known technical debt

As documented on 23/09/2026:

- The Mini Cards / Quick Actions / Themes registries are documented as extensible data sources, but the scheduled routine does not yet reliably read those databases in production; some content remains hardcoded in the generated HTML.
- There is a known synchronization problem between the living artifact, Notion documentation and GitHub access.
- Two historical deviations (26/08 and 02/09) demonstrated the risk of allowing an outdated reference to become the production source without end-to-end validation.

These are implementation issues, not reasons to redesign the ritual itself.

## 🧭 Architectural position in Odyssey

**Bom Dia, Claudi** is a **Schedule Task**, not a Persona.

It is an orchestration layer that brings together multiple Sources of Truth and reusable Skills into one recurring experience.

The morning ritual should not absorb the identity or ownership of those Skills. Its job is to **compose them into a coherent daily experience**.

### Rule of thumb

> **The ritual orchestrates. Skills execute. Sources of Truth provide context. Personas own domains. The schedule provides the trigger.**
> 

## 🔭 Next evolution

The next useful work is not to make the morning ritual bigger.

It is to:

1. preserve the current experience;
2. identify which embedded capabilities are mature enough to become independent Skills;
3. register those Skills separately in the AI Crew database;
4. allow the morning ritual to consume the same Skills it exposes independently;
5. add a manual Run Now path without creating a parallel implementation;
6. progressively replace hardcoded components with their real registries as those integrations become reliable.
